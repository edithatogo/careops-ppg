## Solution admission and recovery

Reuse completed target-specific qualification and existing native ownership. The
portable toolkit supplies source and this procedure; it contains no deployment
profile or native acceptance record. Apply the procedure only to new or still
unqualified components, through the already qualified authentication route.

1. Verify the exact environment, account, solution, approved publisher/prefix and
   four-part version. Classify exact existing flow identities using positive
   native membership or the supported From/Outside Dataverse picker. An empty
   process join or incomplete inventory does not prove non-membership. Exclude
   historical prototypes by identity and purpose, rather than display-name age.
2. Freeze a reserved Stopped copy first. Retain its full definition, stable flow
   ID, creator, state, underlying connections, subscription settings and trigger
   details privately. Callback URLs may carry credentials: compare them privately
   and publish only the result, never their values. Keep original profiles intact.
3. Include only that copy in the selected solution. Conversion can add or replace
   an embedded connection name with a logical connection reference. Read back the
   actual reference-to-existing-connection mapping; changed JSON representation
   alone is neither a broken connection nor proof of equivalent binding. Verify
   definition, identity, creator, state and empty run history separately.
4. Export the actual unmanaged solution and unpack it through the supported CLI.
   Check archive integrity, safe unique paths, typed component identities,
   publisher/version, workflow definitions and declared dependencies. Generate
   deployment settings from that package. Keep reusable unbound settings separate
   from private current-target bindings. Zero declared missing dependencies does
   not establish complete external resources, credentials or target portability.
5. Test membership recovery on the reserved copy: remove it from the solution
   without deleting the native flow, reconcile the retained object, then import
   the frozen package without activation, forced overwrite or global publishing.
   Verify restored membership, the same native identity/definition/connections,
   Stopped state and no runs. Re-export and compare the packaged workflow JSON.
   This proves same-environment membership recovery only, not deleted-target
   recreation, cross-environment import or managed-layer upgrade.
6. After that bounded qualification, take fresh preimages and include only exact
   maintained profiles. Read back their definitions, IDs, creators, prior states,
   connections, subscriptions and trigger links. Reconcile every selected native
   workflow against the final export; retain earlier immutable package hashes.
   Do not import over live originals or rerun completed lifecycle trials merely
   to repeat the recovery proof.

Keep Lists/libraries/columns, Word templates, Office Scripts, pages and Teams entry
points in the existing versioned external-artifact manifest when they cannot be
solution components. Bind each artifact to its authoritative source, hash/version,
owner and recovery route. Inventory actual solution layers and pipeline/Git

## Managed configuration deployment and recovery

Use an identified isolated downstream target through its qualified authentication
route. Reconcile a timed-out operation by its existing handle before retrying.
Do not import a managed package over the originating unmanaged solution, enable
paid capabilities, or create a target solely from this source procedure.

Freeze the managed package and hash, publisher/prefix, four-part version, typed
membership, complete workflow definitions, declared references and source
preimages. Record target suitability and lifecycle privately before import.
Import without activation or forced overwrite; read back the actual managed
version/layers, component identities, full graph and unbound/bound references.
A successful import does not qualify connected execution or output.

For a selected versioned change, stage and upgrade the managed package; verify
the changed graph and removal of the holding solution. Recover with a higher
version containing the prior complete graph, retaining both package hashes.
This is forward recovery, not a downgrade. Test uninstall and frozen-package
reimport only in an owned disposable target: verify absence of the selected
components and preservation of unrelated solutions before reimport. Never use
that shortcut on a maintained source or an environment containing business data.

After recovery, compare the complete definition and declared reference mapping,
final inactive service state, actual run history and unchanged source objects.
Dataverse declarations and expanded Flow service references have different
representations: compare explicit logical-reference/API/invoker mappings rather
than discard arbitrary JSON differences. Recreated workflow-version identities
may differ after uninstall; record them rather than claim identity preservation.

Keep connection binding, fictional runtime/output/edit/retry verification,
production suitability, native Git and deployment-pipeline qualification separate.
A temporary Developer target does not become a durable production destination.
Retain the working source runtime and immutable recovery packages. This portable
procedure contains no tenant bindings or claim that a reader's target is qualified.
