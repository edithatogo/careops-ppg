# Lifecycle source reconciliation

This source increment reconciles32 selected implementation/test paths, seven
supporting regression paths and two canonical integration fixes, and retains
one source-workspace setup test outside the portable toolkit. Existing canonical
adaptations are preserved through a three-way comparison against the recorded
consolidation source, rather than overwriting canonical files with working copies.
The [source increment](../config/lifecycle-source-increment.json) records the
reviewed source-file hashes. It is a dated port receipt, not a requirement that
future reviewed source edits retain old hashes.

The code includes an explicitly fictional append-only relationship journal,
consolidation/deprecation impact checks, effective/recorded-time reconstruction,
immutable lifecycle checkpoint contracts and source-bound reference proposals.
Publication compilers bind expected graph/checkpoint context and destination/
receipt admission to the existing standard SharePoint route. Other increments
preserve per-role consultation identity, complete-history refusal, explicit
no-retry initiation writes and strict same-site source paths.

The new journal/checkpoint/publication compilers are offline, alongside pure
validators and local-copy utilities. Existing read-only maintenance/proof
adapters retain explicit target configuration and separate access qualification;
this port invokes none of them.
They do not deploy or invoke native flows, inherit connection permissions,
authorise policy publication or establish real actor authority. Navigation-copy
output still needs rendering/access qualification in its intended application.
Native bindings, historical runtime receipts, source policy text and working Git
history are excluded. The existing supported/manual routes remain available.

Review and qualification use Python3.15.1, affected Python/Node regressions,
portable-content/privacy checks, full-history secret scanning and source-package
recovery. Real policy decisions and native adoption remain separate.

The complete-package check exposed a verification reader that only recognised
the legacy whole-list URI. It now also accepts the exact bounded top5000 URI,
while rejecting filtered/paged variants, the case list as assurance and all five
continuation markers. Failed first-package evidence is retained; the fix is
qualified separately before the next clean package revision.
